# CarPolo 3D — design notes (shared by all contributors)

C99 + raylib 5.5 game, desktop (Linux, for development/tests) and Android (APK, NativeActivity).
The player drives the owner's **Citroën C4 Cactus (phase 2, 2018+), "Bleu Émeraude" teal-blue paint**
on the **real route** 2000 chemin départemental 15 (La Pécette, Cornillon-Confoux) → Les Grandes
Bastides → Lançon-Provence → A7 → arrival just south of the A54 near Salon/Pélissanne (≈12.6 km).
Goal: as fast as possible, without accidents. Look: "realistic-ish" low-poly 3D (vertex colours,
proper lighting, fog, real terrain, real buildings, real road geometry), not cartoon.

## Repository layout

```
game3d/
  DESIGN.md            this file
  CMakeLists.txt       desktop build (and Android .so build via the NDK toolchain)
  src/                 game sources (C99)
    car_model.c/.h     procedural 3D models: the C4 Cactus + traffic vehicles
    ...                engine (world streaming, terrain, road, vegetation, physics, HUD, audio)
  assets/world.bin     real-world data for the route (generated by tools/world, committed)
  android/             AndroidManifest.xml, res/ (icon), build-apk.sh
tools/world/           Python pipeline that generates game3d/assets/world.bin (+ previews)
```

Locally raylib 5.5 is installed at `/opt/raylib-desktop` (static lib + headers, built from
`/opt/src/raylib`, tag 5.5). Headless rendering for screenshots: `xvfb-run -a -s "-screen 0 1280x720x24"`
(Mesa llvmpipe, OpenGL 4.5). CI fetches raylib 5.5 with CMake FetchContent.

## Coordinate conventions (game world)

- Units: metres. raylib right-handed, **+Y up**.
- **+X = east, +Z = south** (so north = −Z). Y = elevation above sea level (m).
- Local tangent-plane projection around `originLat/originLon` stored in world.bin
  (equirectangular / ENU is fine at this scale: x = (lon−lon0)·cos(lat0)·111320, z = −(lat−lat0)·110540,
  or a proper ENU/UTM-based one — just be consistent and store the origin).

## world.bin (little-endian)

Header: `char magic[4] = "CPW1"; uint32 version = 1; double originLat, originLon;
float minX, minZ, maxX, maxZ;` then a sequence of sections `{ char tag[4]; uint32 byteLength; payload }`
(loaders skip unknown tags).

| tag | payload |
|---|---|
| `STRS` | `uint32 n;` n × `{ uint16 len; char utf8[len]; }` — string table, ids are indices |
| `ROUT` | `uint32 n;` n × 28-byte records: `float x,y,z; float width; uint8 lanes; uint8 lanesForward; uint8 roadClass; uint8 flags; uint16 speedLimit; uint16 nameId; uint16 placeId; uint16 pad;` — the driven centre line from start to finish, resampled every ~2 m and smoothed; `y` = road surface elevation (smoothed, bridges kept level). `width` = paved width of the carriageway we drive on (m). `lanes` = total lanes of that carriageway (2 for a two-way D-road, 3 for one A7 carriageway…), `lanesForward` = lanes in our direction. roadClass: 0 service/unclassified, 1 residential, 2 tertiary, 3 secondary, 4 primary, 5 trunk, 6 motorway, 7 motorway_link. flags: bit0 oneway, bit1 roundabout, bit2 bridge, bit3 tunnel, bit4 built-up area. speedLimit km/h (0 = unknown). nameId: road name/ref ("D15", "A7"…) or 0xFFFF. placeId: locality the point is in, or 0xFFFF. |
| `DEM ` | `float x0, z0, cell; uint32 nx, nz; int16 h[nz][nx];` decimetres. Sample (i,j) is at (x0+i·cell, z0+j·cell). Covers the route bbox + ≥1.5 km margin, cell ≈10 m. Raw terrain (not flattened under roads; the engine conforms terrain to the road). Should be a terrain model (bare earth as far as possible), not tree-canopy. |
| `LCOV` | `float x0, z0, cell; uint32 nx, nz; uint8 cls[nz][nx];` land cover, cell ≈10 m, same coverage. Classes: 0 unknown/grass, 1 forest (pines/oaks), 2 shrub/garrigue, 3 grassland/meadow, 4 cropland, 5 vineyard, 6 orchard/olive grove, 7 residential, 8 industrial/commercial, 9 bare rock/quarry, 10 water, 11 wetland, 12 paved/road. |
| `FAR ` | same layout as `DEM ` but a wide area (≈40×40 km, cell ≈150 m) for the horizon (Alpilles, Étang de Berre, Chaîne de la Fare…). |
| `FARC` | same layout as `LCOV` for the `FAR ` grid (same classes). |
| `BLDG` | `uint32 n;` n × `{ uint16 nv; uint8 kind; uint8 roofShape; float height; float minHeight; (float x, float z)[nv] }` — buildings within ≈600 m of the route, outer ring only, counter-clockwise seen from above (east/north plane), no repeated closing vertex. kind: 0 house, 1 apartments, 2 industrial/commercial/warehouse, 3 agricultural, 4 religious, 5 other. roofShape: 0 flat, 1 hipped, 2 gabled, 3 other/unknown. height in metres (from data or estimated). |
| `ROAD` | `uint32 n;` n × `{ uint16 np; uint8 roadClass; uint8 lanes; float width; uint8 flags; uint8 pad[3]; (float x, float z)[np] }` — other roads within ≈1.2 km (side roads, the other A7 carriageway, the A54…), excluding the pieces the route itself uses. Engine drapes them on the terrain. |
| `TREE` | `uint32 n;` n × `{ float x, z; uint8 type; uint8 pad[3]; }` — mapped individual trees / tree rows (type 0 generic, 1 plane tree, 2 pine, 3 cypress, 4 olive). May be empty. |
| `PLAC` | `uint32 n;` n × `{ float x, z; uint16 nameId; uint8 kind; uint8 pad; }` — localities (kind 0 town, 1 village, 2 hamlet/lieu-dit). |
| `ZONE` | `uint32 n;` n × `{ float s; uint16 nameId; uint16 subId; }` — HUD banners along the route: distance s (m from start) where a zone begins, title and subtitle string ids (e.g. "Cornillon-Confoux", "Lançon-Provence", "Autoroute A7", "Arrivée"). |

## Car models (`src/car_model.h`)

```c
typedef enum { CARMAT_PAINT, CARMAT_PLASTIC, CARMAT_GLASS, CARMAT_CHROME, CARMAT_RUBBER,
               CARMAT_RIM, CARMAT_LIGHT_FRONT, CARMAT_LIGHT_REAR, CARMAT_DECAL, CARMAT_COUNT } CarMatKind;
typedef struct {
    Model body;              // all non-rotating parts; one mesh per material kind used
    int   bodyMatKind[16];   // CarMatKind of body.materials[i]
    Model wheel;             // ONE wheel (tyre + rim), centred on its hub, rolling axis = X
    int   wheelMatKind[8];
    Vector3 wheelPos[4];     // hub positions in car space: FL, FR, RL, RR
    float wheelRadius, length, width, height;
} CarModel;
CarModel BuildCactusModel(void);                       // the player's C4 Cactus
CarModel BuildTrafficCarModel(int kind, Color paint);   // 0 hatchback, 1 estate/SUV, 2 van, 3 semi-truck, 4 small city car
void     UnloadCarModel(CarModel *m);
```
Car space: metres, origin on the ground under the centre of the car's footprint, **+Y up, +Z forward
(front of the car), +X = the car's left side**. Meshes carry positions, normals and vertex colours
(textures only for small decals such as the number plate/"CACTUS" badge). The engine renders every
material with its own lighting shader (sun + sky ambient + fog, glossy specular/fresnel for
PAINT/GLASS/CHROME, emissive-ish lights), choosing parameters from the material kind.

## Rendering rules

- OpenGL ES 2.0 on Android (GLSL `#version 100`), OpenGL 3.3 on desktop (`#version 330`): shaders are
  written once with a small version prefix.
- Big static geometry is merged per route chunk (≈100 m of route); chunks are built on a background
  thread (desktop/Android) or in time slices on the main thread (web, `jobStep` budget) and unloaded
  around the player (streaming). OpenGL ES 2.0 is also what the web build uses (WebGL 1).
- Textures are procedural and generated at start-up (`textures.c`): 4 ground textures per material
  group (terrain: grass, garrigue, soil, limestone; road: asphalt, gravel, dirt, concrete; detail:
  stucco, roof tiles, bark, concrete) plus a foliage atlas with alpha. Vertex contract (`render.h`):
  `texcoord` = uv in texture tiles, `texcoord2.x` = material id 0..3 (fractions blend the four
  textures), `texcoord2.y` = 1 for flat vertex-coloured surfaces, `color.rgb` = tint, `color.a` = opacity.
  Foliage (leaf cards) is a separate alpha-tested, two-sided mesh per chunk (`gLitCut`); a fourth
  per-chunk mesh holds instances of the low-poly model pack (`assets/trees.bin`, format in
  `tools/treepack.py`), used only within 90 m of the road because each model is 2-5k vertices.
- Sun shadows: orthographic 340 m shadow map centred 70 m ahead of the car, depth packed in RGB
  (works on GLES2/WebGL1), PCF on desktop, sampled on texture unit 7 by the lit shaders.
- Terrain chunks are indexed (16-bit, shared vertices on a half-cell grid); the rest stays non-indexed.
  A 40 m "mid" corridor mesh and the 300 m far mesh (flat colours) are always drawn under the chunks,
  so streaming never shows holes; new chunk details rise from the ground over 1.5 s (`rise` uniform).
- One directional sun (afternoon, from the south-west), hemispherical ambient, exponential aerial haze
  (`1 - exp(-d/9000)` at high quality) warmer towards the sun; clip planes 0.25 m .. 30 km.
